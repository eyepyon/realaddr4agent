# フロントエンド仕様

## 目的と提供状態

本書は公開サイト、利用者画面、人間承認画面、運用者画面のUI契約である。リポジトリは仕様段階であり、画面・API接続・ドメイン公開はいずれも未実装・未検証。実装時の予定originは `https://address.chain.tokyo`。ドメイン/DNS設定はユーザー（運営者）担当であり、公開済みを意味しない。

想定構成はReact/Viteによる公開ページの静的prerenderと、同一origin上のFastify APIを利用する動的な認証UI。公開ページはJavaScript実行前にも見出し、概要、ナビゲーションが読めるHTMLを出す。人間承認画面はserver session、利用者画面は既存Agent Bearer API、管理画面は運用者向け認証契約を情報源とし、ブラウザの値だけで権限や状態を決めない。

## 見た目と共通部品

一般的な業務SaaSの明るく落ち着いた画面とする。白い本文面、薄いグレーの背景・境界、控えめな青のリンク・主ボタンを使う。暗いネオン、強いグラデーション、ガラス表現、装飾目的の暗号資産モチーフは使わない。本文は読みやすい日本語を主とし、API識別子やネットワーク名は必要箇所だけ併記する。

デザイントークンの初期値: 背景 `#f5f7fa`、面 `#ffffff`、本文 `#172033`、補助文字 `#5c667a`、境界 `#d9e0e8`、主色 `#2457c5`、危険 `#b42318`。本文16px/行高1.5、補助14px、ページ幅は最大1200px、本文列は最大760px。4px基準の間隔（4/8/12/16/24/32/48px）、8px角丸、控えめな影を共通化する。色だけで状態を示さない。

再利用部品は `PublicHeader`、`AppShell`、`AdminShell`、`PageHeader`、`Breadcrumbs`、`StatusBadge`、`DataTable`、`Pagination`、`FormField`、`Notice`、`ConfirmDialog`、`CopyButton`、`TraceDetails` とする。状態語彙はAPIのstatusをそのまま表示し、日本語ラベルと意味の説明を添える。日時は利用者のlocaleで表示し、詳細にUTC値を確認できるようにする。

## ルートと画面

| パス | 用途・主な内容 |
| --- | --- |
| `/` | 公開トップ。見出し「AIエージェントの住所利用を、人間が管理できる形で。」、仕組みの3段階（契約・ENS照合・人間の転送設定承認）、仮想区画の説明、公開拠点を確認する導線、開発者向けCTA。稼働していないスポンサー連携や実住所サービスを稼働中と表示しない。 |
| `/developers` | API/CLIの利用案内、wallet主体とAgent認証の概要、payment intent→人間承認URLの流れ、OpenAPIへのリンク、対応ネットワークのsandbox表示。秘密鍵を画面やpromptへ貼らない注意を短く示す。 |
| `/faq` | 仮想区画は物理階でないこと、World認証と法的本人確認の違い、承認後にできること、実郵便を扱わないこと、テストネットと本番の違いを説明する。 |
| `/app` | 接続walletの署名で既存Agent Bearer APIに認証する利用者概要。自分の契約、画面で取得済みの決済保留、人間承認待ちへのリンクを示す。件数は読み込んだページの範囲を明記し、全DB件数と誤認させない。空状態に「契約はまだありません」と拠点閲覧/開発者案内を示す。 |
| `/app/subscriptions` | Agent Bearerで取得する自分の契約一覧。拠点、仮想区画番号、状態、期限、ENS状態、転送設定状態、詳細リンク。更新は既存CLI/操作への引き渡しとして案内し、ブラウザで署名・決済する未定義フローを作らない。 |
| `/app/subscriptions/{id}` | 契約詳細。拠点表示名、仮想区画、契約状態/期限、決済receipt、ENS名とSepolia同期状態、転送設定可否と宛先登録済みフラグ。Agent向け表示/APIには宛先本文を含めない。 |
| `/app/payments` | GET `/v1/payment-intents`を使うpayment intent一覧と詳細リンク。金額、ネットワーク、作成時刻、状態、intent IDを表示する。settling/reconcilingは「確認中」と再試行目安を出し、同じintentの状態取得を促す。件数は取得ページの範囲を明記する。 |
| `/approve/{id}` | 人間専用承認。未検証時は一般的な案内だけを表示し、URLだけで契約情報を出さない。wallet接続・所有確認→対象Agent/契約と権限の説明→fresh World認証→明示的な許可/拒否の順に進める。 |
| `/admin` | 運用者専用の概要と主要キュー。運用者ナビゲーションは[管理画面仕様](admin.md)に従う。 |

`/approve/{id}` の確認文は「この操作で郵便転送設定を有効にします。転送先はこの後、あなたが入力します。郵便物の受領・発送や送料の支払いは行いません。」とする。許可ボタンは認証後にだけ有効化し、対象、期限、接続walletをその直前に再表示する。World成功だけで承認済みにせず、APIが `applied` を返すまで完了表示をしない。

承認適用後、同画面に「郵便転送可」「転送先未登録」と人間用フォームを表示する。氏名、郵便番号、都道府県、市区町村、番地、任意建物名を本人が入力する。送信前に確認表示、保存成功後に「転送先登録済み」を出す。宛先は認証済み人間のセッションでのみ取得・編集できる。Agentには有効状態と登録有無だけを返し、agent指示やUI自動化で人間の承認・入力を代行しない。

利用者画面は契約・決済・ENSの状態を読み取り中心にまとめ、運用者画面の検索、監査、例外処理は管理画面側に置く。管理者も完全な転送先住所、World ID/subject識別子を表示しない。管理APIの詳細と操作範囲は[管理画面仕様](admin.md)を参照。

利用者画面のBearer認証はAPIのwallet challengeを表示し、接続walletでchallengeへ署名して既存のAgent Bearerを取得する。発行tokenは画面が開いている間だけメモリに保持し、localStorage/sessionStorage、URL、ログ、フォームに保存・表示しない。APIキー入力・発行フォームや秘密鍵入力欄は設けない。ページ再読込やtoken失効後は再接続・再署名を案内する。契約データはサーバーに永続化されているため、再認証後に再取得できる。

利用者APIが返す転送先情報は有無のフラグに限る。完全な転送先は人間セッション内の人間向けフォームでだけ取得・表示する。利用者の契約更新導線はCLIなど既定の操作方法へ引き渡す。ブラウザ内支払い署名やIntercepta資格情報の配布方法は仕様化されるまで実装しない。

## 操作、応答、エラー

初期表示はスケルトンまたは明示した読み込み文を使い、レイアウトの大きな移動を避ける。空状態には次の行動を案内する。API失敗は利用者向けの説明、再試行可否、必要ならtrace IDを表示し、内部スタック、secret、住所、識別情報を含めない。外部サービス未応答・不明な判定は成功や安全として表示せず、「確認できないため保留」とする。

決済の `202` は「決済処理を受け付けました。確定を確認中です」と表示し、契約発行済みと混同しない。`fulfilled` とsubscription IDを受けて初めて完了とする。リスク拒否、区画競合、期限切れ、依存停止は各API error codeに対応した日本語の説明と次の手順を出す。二重送信を防ぎ、再送時は同じintent/冪等操作を継続する。

状態の再取得はAPIの `retryAfterSeconds` を尊重し、画面が開いている間に限り間隔をあけて数回まで行う。無限ポーリングや頻繁な自動更新はしない。完了しない場合はIDを残し、利用者が後から再表示して確認できるようにする。

## アクセシビリティと画面幅

すべての入力に可視ラベル、必須/任意、形式、エラーを関連付ける。キーボードだけでナビゲーション、ダイアログ、wallet/World開始、表操作を完了でき、フォーカス表示を明確にする。状態変更は読み上げ可能な通知で伝える。見出し階層、リンク文言、コントラスト、エラー時のフォーカス移動を整える。

幅768px以上では公開ヘッダーと管理/利用者の左ナビ＋本文を使う。狭い幅ではナビを開閉式にし、テーブルは主要列をカード表示または横スクロール領域に収め、ページ全体の横はみ出しを避ける。フォームは一列にし、主要操作は画面幅に応じて押しやすい幅を確保する。

## 最小の手動画面確認

実装後、公開トップを狭い幅と広い幅で開き、初期HTMLに主要説明があり、ナビと文字が読みやすいことを確認する。テストデータ上の利用者一覧で仮想区画、保留決済、ENS pending/errorを確認し、幅を狭めても操作できることを確認する。承認URLでは未検証状態に非公開情報がなく、正しい順序でのみ許可でき、承認後に人間用フォームが出ることをsandboxで確認する。実サービス接続・成功結果は実際に検証するまで記載しない。
