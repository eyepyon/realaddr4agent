# 利用規約v1の採用記録と提供準備

対象: T-02/T-08/T-19。2026-09-26に[利用規約バージョン1](terms.md)を正式採用した。正式識別子は `realaddr-v1`。本文の単一正本から `/terms` の初期HTMLを生成し、APIの `TERMS_VERSION`、Web buildの `VITE_TERMS_VERSION`、配備時の指定をこの版に一致させる。本文を提示して利用者本人または権限を与えられた代理者の同意を得た利用から適用し、既存の開発用署名や原案閲覧にさかのぼって同意を成立させない。

正式version未確定というeventイメージ作成の待ち条件は解消した。これは実配備、公開、外部接続、提供開始または法務確認の完了を意味しない。保護された設定への投入と実runtimeへの反映は配備工程で確認する。

## 本文へ反映した確定仕様

- 住所利用の期間はx402の確定支払いで決まる。30日単位で、自動継続課金はしない。World承認は住所購入・更新の条件ではない。
- 同じ契約・owner・policy・宛先の適用済み同意は無期限。期限切れは設定利用だけを停止し、同じ契約のpaid renewal/revivalで再承認を要求しない。宛先変更は新たな人間承認を要し、取消し・security suspensionをrenewで解除しない。
- ENSは任意の初回別料金で、標準とcustomを合算しない。住所更新は購入済みENSの維持を含み、同じleaseの復旧で再課金しない。
- 通常の任意取消は返金しない。照合後に復旧不能な発行失敗が確定した注文だけ、元payerへ同一network/assetで全額を自動返金する。gasは運営負担、他の有効期間・商品へ影響させない。強行法規上の権利を除外しない。
- eventはtestnet。実郵便受領・発送・送料決済を含まない。機能の実装・外部接続・公開を完了済みと表現しない。

## 提供開始までの準備

以下は本文の採用だけで実施済みにしない。提供条件を変更する場合は、要件・料金・API・画面の影響を先に確認し、規約の実質的な変更は新しいversionとして扱う。v1に同意した記録が指す本文を後から置換せず、公開した版とGit履歴を保持する。

| 項目 | 必要な確認 |
| --- | --- |
| versionの反映 | eventは `realaddr-v1` を明示設定し、API・Web・配備の一致を確認する。local demo用versionを正式な同意として扱わない |
| 申込主体と代理 | 個人・法人等の受付範囲、代理権の確認方法、年齢等の利用資格を確定する。AgentやWorld認証のみを法的主体・代理権・KYCの証明にしない |
| 連絡と表示 | 利用者が使える問い合わせ窓口、通知方法、必要となる事業者表示を確定する。未確認の連絡先や提供拠点を作らない |
| 情報の取扱い | データ項目、目的、providerへの提供・委託、保管場所・保存期間、削除・開示等の窓口を整理し、プライバシー案内を用意する。未確認の保存期間や外部サービス保証を約束しない |
| 法務確認 | 住所の許容用途、契約成立・代理、返金、停止・終了、責任、準拠法・管轄、表示義務について、実際の提供形態に即して確認する。第15条の日本法・法定管轄は採用済みだが、専門家による個別確認を実施したとの主張ではない |
| 正式同意の記録 | 公開する確定本文と署名に含むversionを一致させ、本文と適用時点を追跡可能にする。既存の開発用署名を後から新規約への同意とみなさない |

正式な規約ページは他の公開ページと同じ `index,follow` とし、sitemapとllms.txtに掲載する。公開ナビゲーション・footer・利用者認証前の同意欄から到達できる。閲覧だけでは同意を意味しない。署名に含めるversionと本文のversionを一致させる。
